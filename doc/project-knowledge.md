# commands — project knowledge

What the sessions have learned about this project, beyond what the code
and the git history already say. Updated by `capture-session-knowledge`.

Last updated: 2026-08-01

## 1. What this project is, and what it is not

- **One executable, many commands.** Personal Unix commands written in
  Common Lisp, all compiled into a single SBCL image dispatched on
  argv[0] (busybox-style). The `README` records why the older
  one-script-per-command model (clisp `#!`, cl-launch) was abandoned.
- It is not a library: `sources/commands/*.lisp` are leaf programs; only
  `sources/script.lisp` (the framework) is shared.

## 2. Layout, entry points, and how the pieces fit

- **Build chain:** `make` runs SBCL on `generate-commands.lisp`, which
  loads `generate.lisp` (quicklisp setup, image saving) and
  `builder.lisp` (the `*all-commands*` list and the compilation loop).
- **`builder.lisp` sequence:** `register-commands` reads each source's
  `(command …)` form (`read-command-form` in `sources/script.lisp`) →
  `quickload-command-dependencies` preloads every declared
  `:use-systems` → each command is compiled and loaded with `*package*`
  bound to its own `COMMAND.<NAME>` package → the image is saved with
  toplevel `dispatch-command`, which dispatches on the invocation name.
- **`bin/commands`** is a wrapper (`commands-wrapper.sh`) that
  `exec -a "$(basename "$0")"` the real image
  `bin/commands-<OS>-<arch>[-<host>]` (`COMMANDS_BIN` overrides the
  choice). Per-command names are symlinks to it, created by
  `bin/symlink-commands`, itself generated by the build. Neither the
  image nor the symlinks are tracked by git (only `bin/.keep`).
- **The framework** (`sources/script.lisp`, package `SCRIPT` =
  `COM.INFORMATIMAGO.COMMAND.SCRIPT`) provides the `command` macro, the
  options DSL (`options`, `option`, `standard-options`,
  `bash-completion-options`), the `ex-*` exit codes, and the dispatcher.
- Informatimago libraries are found under `~/src/public/lisp` via the
  ASDF directories configured in `generate-commands.lisp`, not via the
  quicklisp dist.

## 3. How to build, run, and test

- Build (verified 2026-08-01, SBCL 2.6.3, macOS arm64):

  ```sh
  make
  ```

  Exit 0 with no `;N failures` line means every command compiled and
  loaded cleanly; any failure makes `generate-commands.lisp` exit 1
  before saving the image.

- Run a freshly built command without installing (the wrapper needs
  argv[0] to be the command name):

  ```sh
  ln -sf commands bin/next-tweet
  bin/next-tweet --count
  ```

## 4. Conventions and invariants (all commands)

See [AGENTS.md](../AGENTS.md) for the directive form of these; details
and rationale:

- **Command form first.** The `(command :use-systems …)` form is the
  first form of the file. Two independent reasons: anything defined
  before it lands in the shared `SCRIPT` package
  ([issue 003](../issues/open/003-in-package-script-antipattern.md)),
  and `read-command-form` reads with `*read-eval*` NIL, so the form must
  precede any `#.` in the file (commit 0d07a15).
- **`:use-systems` is the preload list.** It is harvested *before* any
  command is compiled; it is not merely documentation of what the
  command uses (see Pitfalls).
- **No load-time execution**
  ([issue 005](../issues/open/005-remove-load-time-execution.md)): a
  top-level form runs at build time inside the image shared by all the
  commands.
- **Standard CLI**
  ([issue 001](../issues/open/001-cli-homogenization.md)): options via
  the `options`/`option` DSL ending with `(standard-options)` and
  `(bash-completion-options)`; `main` receives the argument list, calls
  `(parse-options *command* arguments)`, and returns an `ex-*` code
  (`ex-ok`, `ex-usage`, `ex-unavailable`, `ex-software`, …). `-h` and
  `-V` print and exit 0. Per-command version in the `command` form's
  `:version` slot (closed issue 006).
- **Zero warnings.** `compile-and-load-command` counts any `warnings-p`
  from `compile-file` (style-warnings included) as a failure.

## 5. Decisions

- **2026-08-01 — `read-command-form` binds `*read-eval*`, not
  `*read-suppress*`** (commit 0d07a15). With `*read-suppress*` T, `READ`
  returns NIL for every form, so the command form was never recognised,
  no `:use-systems` was ever registered, and the preload step loaded
  nothing. Rejected alternative: keeping the suppression and relaxing
  the builder's warnings-as-failures check — that would also let real
  warnings in command code pass.
- **2026-08-01 — the image is saved with `:save-runtime-options t`**
  (commit c92c4ea). Without it the SBCL runtime intercepts `--help`,
  `--version`, `--core`, … before the dispatched command sees them.
- **Single-image model** (README, 2019 era): one image, argv[0]
  dispatch; the price is the no-load-time-execution rule.

## 6. Pitfalls

- **";Failed to compile <command>" and the only diagnostic is a
  STYLE-WARNING from a foreign system** (e.g. ironclad's "redefining
  IRONCLAD:BLOCK-LENGTH in DEFGENERIC"). Cause: the system was not
  preloaded, so it was quickloaded *inside* the command's
  `compile-file`, and its load-time warning set `warnings-p`. Fix:
  declare the system in the command's `:use-systems`; if every
  `:use-systems` seems ignored, re-check `read-command-form` against
  commit 0d07a15.
- **A command dies at run time with "MAIN is undefined"** though it is
  in the image: a load-time form aborted the loading of its fasl during
  the build (historical case: columnify's `stty` probe, issue 005).
- **Every command misbehaves the same way with no option given** (e.g.
  all verbose): some file mutated a shared `SCRIPT` special at load
  time (historical case: svn-locate-revision's
  `(defparameter *verbose* t)`, issue 005). Inspect top-level forms of
  recently-touched commands.
- **`<cmd> --help` prints the SBCL runtime usage**: the image was saved
  without `:save-runtime-options t` (fixed in c92c4ea; keep the flag
  when touching `generate.lisp`).
- **Patches touching the command lists reject** (`Makefile.rej`,
  `builder.lisp.rej`) whenever neighbouring command names changed; the
  lists are alphabetical, re-apply the one-line insertions by hand.

## 7. Environment and tooling

- Build host observed 2026-08-01: macOS Darwin arm64, SBCL 2.6.3;
  `SBCL_OPTIONS = --noinform --no-userinit --non-interactive`. The
  Makefile removes `~/.cache/common-lisp/sbcl-*<tree>` first, so command
  fasls always recompile (they are written next to the sources and
  gitignored).
- Four push remotes (github, gitlab, framagit, and a local bare repo);
  the working branch is merged into `master` and `master` pushed to all
  four.
